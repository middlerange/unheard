## Customization Template

| Element | Example |
|---------|---------|
| `[CUSTOMER]` | "A SaaS PM at [COMPANY]" or "Our team at Userorbit" |
| `[BEFORE]` | "90% churn by Week 1 and wondering why" |
| `[AFTER]` | "45% Week 1 retention and profitable unit economics" |
| `[SPECIFIC PROBLEM]` | "Users signed up but never returned after onboarding" |
| `[FIRST SOLUTION]` | "Built an onboarding tutorial" |
| `[SPECIFIC REASON]` | "Tutorial was feature-focused, users got confused" |
| `[KEY INSIGHT]` | "Retention isn't about features, it's about proving value" |
| `[SPECIFIC ACTION]` | "Removed tutorial, created simplified path to core action" |
| `[METRIC 1]` | "Day 1 return rate from 10% to 30%" |

## Platform Rules

- **LinkedIn:** Full narrative (4 acts) + metrics + lesson (emotional + data-driven)
- **Twitter:** Teaser with key insight + metric + link (attention-grabbing)
- **Reddit:** Case study format (conversational, invites discussion)

## Pre-Publish Checklist

- [ ] Story is specific (not generic "team struggled then succeeded")
- [ ] Customer permission (if real customer, make sure they're okay with it)
- [ ] Timeline is clear (when did this happen, how fast was the change?)
- [ ] Metrics are specific (percentage point changes, not "much better")
- [ ] Lesson is universal (applies beyond this specific story)
- [ ] Narrative is engaging (not just data dump)

## Engagement Notes

- **LinkedIn Engagement:** VERY HIGH - Stories create connection + social proof
- **Twitter Engagement:** MEDIUM-HIGH - People want the story behind the metrics
- **Reddit Engagement:** HIGH - Case studies generate discussion + credibility
